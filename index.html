OS-Helix

Unifying GUI Interaction and Code Execution in Native Computer-Using Agents

We present OS-Helix, an end-to-end trained computer-using agent that treats GUI interaction and code execution as actions of one policy.

Executable desktop states: Applications and authentic artifacts are composed into reproducible task environments.
Grounded, verifiable tasks: Exploration proposes instructions and an independent evaluator checks the final state.
Hybrid training: Filtered GUI/code trajectories initialize the policy before online RL with Step-balanced GSPO.

At a glance

OS-Helix-27B-RL reaches 66.44% success on OSWorld-Verified and 63.87% on WindowsAgentArena.

Core idea: A GUI tool and a code tool are most useful when one policy learns how to choose and coordinate them during real desktop tasks.

Real desktop automation is neither purely visual nor purely programmatic. OS-Helix unifies GUI actions and code execution in one action space. Its training pipeline composes applications with authentic artifacts, synthesizes environment-grounded tasks with independent evaluators, and learns from filtered hybrid trajectories followed by online reinforcement learning.

A native hybrid policy can ground itself in the visible interface while using code for precise manipulation of files and structured state. The policy learns modality routing through training rather than through inference-time tool access alone.

OS-Helix Framework

OS-Helix has four stages. Application–artifact composition first creates executable desktop states. Environment exploration then produces grounded instructions, while a separate evaluator makes each task verifiable. Filtered GUI/code trajectories provide a supervised cold start. Finally, the policy improves through online interaction with live desktop environments.

Application–Artifact Composition

Applications are paired with authentic artifacts through a compatibility graph. The resulting Ubuntu states are reproducible and provide realistic files and interfaces for task synthesis.

Environment-Grounded Task Synthesis

An Exploration Agent observes the current environment to propose a task and its success conditions. A separate Evaluator Agent checks the final state without prescribing whether the solution should use GUI actions, code, or both.

Step-balanced Reinforcement Learning

After supervised fine-tuning on filtered hybrid trajectories, OS-Helix trains in live desktop sandboxes. Step-balanced GSPO gives GUI and code action steps comparable weight, preventing long code actions from dominating mixed-action optimization.

Main Experiments

OSWorld-Verified

The paper evaluates OS-Helix on 361 OSWorld tasks after excluding eight Google Drive tasks. The 27B model improves from 46.50% for its matched Qwen3.5-27B hybrid baseline to 62.75% after SFT and 66.44% after RL.

Analysis

How efficiently does the agent act?

Across complete tasks and outcome-matched subsets, the trained policy uses fewer interactions than the matched baselines. It also covers more successful tasks under smaller step budgets.

Why balance GUI and code steps?

Under the paper's controlled RL comparison, standard GSPO reduces success to 60.47% and raises the code-action rate to 40.0%. Step-balanced GSPO reaches 66.44% while keeping the code-action rate at 26.1%, close to the 27.9% SFT starting point.

Case Study

GUI and code in one workflow

Representative trajectories show the agent moving between visible interfaces and programmatic operations as the task changes. GUI interaction provides grounded observations; code handles precise or repeatable steps.

Conclusion

OS-Helix trains a native hybrid computer-using agent through reproducible desktop states, verifiable tasks, filtered GUI/code demonstrations, and online RL. Its results support learned coordination between the two action modalities and show transfer beyond the training platform.
